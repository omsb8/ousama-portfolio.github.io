## Updating the site

Edit `index.html`. Keep the top section concise: current role, degree, earned certifications and active technical focus. Add a project only when its source or demonstration is ready. Use the problem, approach, evidence, limitations and your own contribution in each case study. Verify claims and distinguish team work from individual contributions.

Use the existing GitHub Pages configuration; no new domain, repository rename, or hosting migration is required by this change. Confirm the current live URL before changing links on a résumé or LinkedIn.

The Power BI screenshot is referenced from the public project repository. Update that URL if the screenshot moves.

## Which links go where

- Résumé and LinkedIn → public portfolio and GitHub.
- Public portfolio → selected repositories and LinkedIn.
- GitHub profile → selected repositories and the verified portfolio URL.
- Private Career Compass → public portfolio, GitHub, project repositories and internal career records.
- Keep Career Compass's applications, networking notes, internal role links and growth planning private. Do not add it as a public portfolio navigation item.

## Maintenance rhythm

- Weekly: update private career tasks and applications.
- At a completed milestone: refresh the relevant public project and portfolio entry.
- Quarterly: review profile copy, public links and featured projects.
- Academic archives: preserve historical context; fix broken links when encountered, without rebuilding every exercise.
